# 関西俳句バトル2027 GAS 設定手順

`khb2027_webapp.gs` をGoogle Apps Scriptプロジェクトへ貼り付け、以下を設定してから
Web Appとしてデプロイする。

学年の選択式・姓名間スペースの検証を反映する際も、更新した `khb2027_webapp.gs` を貼り付け、
既存Web Appのデプロイを新しいバージョンへ更新する。メンバーの学年は中1〜中3・高1〜高3、
メンバーと責任者の氏名は姓名間に全角スペースを入れるよう案内し、半角スペースでも修正せず受け付ける。
紹介文の250〜280字判定は、改行（LF・CRLF・CR）を1字として画面とGASで統一する。
この判定の更新時もWeb Appのデプロイを更新する。
合同チームは、登録した全校から1人以上の選手が所属することも検証する。
選手が0人の学校がある場合は保存前に拒否するため、この変更もGASの再デプロイが必要になる。

## 1. 手入力する設定

`khb2027_webapp.gs` 冒頭の `KHB_CONFIG` に、コメントを参照して設定する。
締切の例は本番の締切ではないため、必ず実際の日時に置き換える。

| 設定 | 値 |
| --- | --- |
| `KHB_SPREADSHEET_ID` | KHB用スプレッドシートのID |
| `KHB_ENTRY_DEADLINE_JST` | 例：`2026-10-31T23:59:59+09:00` |
| `KHB_SUBMISSION_DEADLINE_JST` | 例：`2026-11-30T23:59:59+09:00` |
| `KHB_ADMIN_EMAIL` | 運営控えのBCC送信先（初期値：`klea.ex+khb@gmail.com`） |
| `KHB_REPLY_TO` | 返信先・本文の問い合わせ先（初期値：`klea.ex+khb@gmail.com`） |
| `KHB_SITE_ORIGIN` | `https://kleaex.github.io` |

スクリプトプロパティに同名の設定がある場合はそちらが優先されるため、
既存プロジェクトではプロパティ側も確認する。

兼題は **`khb2027/js/kendai.json` のみ**で管理する。GASへの転記は不要。
`dai1`〜`dai3` がリーグ戦①〜③、`dai4` が決勝戦で、各配列の2番目に
`「兼題」`、3番目に `（読み）` を記載する。サイトに公開してから投句受付を開始する。
現在のプレースホルダー `「」` のままでは、投句は保存されない。

GASは `KHB_SITE_ORIGIN` + `/khb2027/js/kendai.json` を `UrlFetchApp` で取得する。
最終送信ごとに1回取得し、全4兼題を検証してから保存・上書きを行う。
取得失敗、JSON不正、兼題未設定の場合は、新規保存・上書き・履歴退避・受付メール送信を行わず、
再試行を案内する（失敗は運用ログへ記録する）。エントリー受付は兼題の取得に依存しない。
メールにはサイトと同じ兼題・読みを記載する。

**秘密値だけはコードに書かず**、Apps Scriptの「プロジェクトの設定」→
「スクリプト プロパティ」で `KHB_HMAC_SECRET` に32文字以上のランダムな値を設定する。

`KHB_HMAC_SECRET` は公開リポジトリ、HTML、JavaScript、スプレッドシートのセルへ
書き込まない。紛失・漏えい時に変更すると既存エントリーの照合キーが無効になるため、
その場合は管理者用の再生成処理を別途実行する。

## 2. Web Appのデプロイ

1. スクリプトのタイムゾーンを日本時間に設定する。
2. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選ぶ。
3. 実行ユーザーはスプレッドシートとメール送信を行える運営アカウントにする。
4. アクセス権は、サイト利用者がPOSTできる設定にする。
5. 発行された **`/exec` URL** をコピーする。
6. `khb2027/js/gasConfig.js` の `GAS_WEB_APP_URL` に設定する。

`UrlFetchApp` に必要な外部通信の権限も承認する。権限スコープをマニフェストで手動指定している場合は
`https://www.googleapis.com/auth/script.external_request` を含める。

`/dev` URLは開発者だけが使うテスト用であり、本番サイトには設定しない。

## 3. 初回確認

テスト用スプレッドシートと短いテスト期限を使い、以下を確認する。

1. エントリー送信で `エントリー` シートが作られ、照合キーが保存される。
2. 同じチーム名・メールでの重複エントリーが拒否される。
3. エントリー済みのチームが投句できる。
4. 未エントリー、または一文字でも異なるチーム名・メールでは投句できない。
5. 二回目の投句では、保存前に上書き確認が表示される。
6. 上書きを承認すると、旧内容が `投句履歴`、新内容が `投句` に残る。
7. 締切後のエントリー・投句・上書きがいずれも拒否される。
8. エントリーの参加確認・入力確認・連絡確認が未チェックなら拒否される。
9. エントリーメールに全学校名、回答内容、確認結果、日本時間の送信日時が載る。
10. 投句メールに全14句と対応する作者名、兼題、特記事項、宣誓、日本時間の送信日時が載る。上書き時も最新内容が載る。
11. 両メールの宛名がチーム名となり、運営へのBCCと `klea.ex+khb@gmail.com` への返信先が設定される。
12. 公開JSONの兼題・読みと投句メールの内容が一致する。GAS側への兼題設定は不要。
13. JSON取得失敗・不正なJSON・未設定兼題の場合、新規投句も上書きも保存されず、再試行の案内が表示される。
14. JSON取得中に締切を過ぎた場合も、ロック取得後の期限確認で保存されない。

テストでは、ローカルファイル直開きではなく、HTTPでサイトを配信して確認する。

## 4. 受付メール

提示されたエントリー・投句のテンプレートを使用する。
エントリーの誤りや変更はフォーム再送ではなく、実行委員会への連絡を案内する。
同じチーム名・メールでの重複エントリーは引き続き拒否する。
投句の上書き受付は件名に「上書きして」を付け、本文には今回受け付けた全内容を記載する。

メールはGASの実行アカウントから送信される。`KHB_REPLY_TO` は差出人アドレスの変更ではなく、
返信先と本文の連絡先を指定する設定である。

旧版の `エントリー` シートがある場合は、初回アクセス時に `inputConfirmationAt` 列を末尾へ追加する。
既存行の同列は空欄のまま保持し、過去の入力確認を後から確認済みとして扱わない。
