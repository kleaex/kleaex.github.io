# 関西俳句バトル2027：GAS直送信・エントリー照合 実装仕様

## 目的

エントリーと投句を、Google Formを経由せず、サイトのフォームから
Google Apps Script（GAS）Web Appを通じてGoogle Sheetへ記録する。

投句時には、入力されたチーム名とメールアドレスが有効なエントリーと
一致することを確認する。チーム照合は取り違えを防ぐ簡易チェックで、
登録メールに届く確認コードによる本人確認を別に実施してから、名簿取得と投句を許可する。

## 確定仕様

### 照合

- 照合対象はチーム名とメールアドレス。
- 値の正規化は行わない。全半角、空白、大文字小文字を含め、入力値そのものを
  照合に使う。
- クライアントとGASの双方で、必須、文字数、メール形式、前後空白の有無を
  バリデーションする。
- GASは `v1|<チーム名>|<メールアドレス>` を入力とし、Script Propertiesにだけ
  保管する秘密値による HMAC-SHA-256 を照合キーとして生成する。
- 秘密値、照合キー一覧、照合ロジックの判定結果を静的サイトへ置かない。

### エントリー内容

- エントリーフォームは1回につき1チームを登録する。複数チームを出場させる学校は、チームごとに送信する。
- `出場予定チーム数` は学校としての予定数（1〜3）を記録する。
- 合同チームには `合同チームである` チェックボックスを学校名欄の前に設ける。チェック時は
  学校名欄を2校目まで表示して必須にし、追加ボタンで最大5校まで学校名欄を増やせるようにする。
  チェックなしの場合、2校目以降の値は送信しない。
- 合同チームで同じ学校名を複数登録することは、画面とGASの双方で拒否する。
- 合同チームは登録したすべての学校から1人以上の選手が所属することを画面とGASで検証する。
  選手が0人の学校名を表示して送信を止め、学校名・所属校・人数・合同チームの設定変更で再判定する。
- チーム人数（3〜5人）に合わせて、メンバーごとの氏名・学年を必須入力にする。
  学年は `中1`・`中2`・`中3`・`高1`・`高2`・`高3` の選択式とし、GASでもリスト外の値を拒否する。
  合同チームでは所属校も必須とし、入力済みの学校名から選択する。単独チームでは所属校を送らない。
- メンバー・責任者の氏名は、姓と名の間に全角スペースを入れるよう案内する。半角スペースでも修正せず受け付ける。
  画面とGASで姓名間のスペースを検証する。
  前後だけの空白やタブだけの区切りは認めない。複数語の氏名を許容し、入力表記は変更しない。
- 氏名は比較時に全角・半角スペース、タブなどの空白を除き、空白だけの入力を拒否する。
  氏名の重複は入力ミスでないか確認する警告にする。同姓同名は学年・所属校で区別する。
  氏名・学年・所属校のすべてが一致するメンバーは、実行委員会への連絡を案内して送信を止める。
  投句の作者名も同じ基準で登録氏名と照合する。入力・保存する表記は変更しない。
  メンバーの入力順はパンフレットの掲載順として保持する。
- 責任者の役割は `顧問`、`コーチ`、`選手`、`その他` から選択する。`その他` を選んだ場合だけ、役割の具体的な記載欄を表示して必須にする。
- 参加確認・入力確認・連絡確認を必須にし、確認日時を保存して受付メールへ回答内容を記載する。
- 同じチーム名・メールの重複エントリーは拒否し、誤りや変更は実行委員会への連絡を案内する。
- 紹介文は画面とGASの双方で250〜280字を検証する。改行はLF・CRLF・CRとも1字、空白も1字として数える。
  Unicodeコードポイントで計数し、画面に現在の文字数を表示する。HTMLの `minlength`・`maxlength` による別基準の判定は使わない。
  計数時だけ改行形式を揃え、入力値・保存値の改行や表記は変更しない。
- チーム名には学校名を含めること、学校名は正式名称で記すことは、画面で案内し、運営が必要に応じて確認する。これらを文字列だけで機械的に判定しない。

### 受付期限

- エントリー、投句とも、GASが日本時間の締切日時を基準に判定する。
- クライアント側の時計や画面表示は判定に使用しない。
- 締切後のリクエストは、照合・保存・メール送信を行わず、受付終了を返す。

### 兼題の管理

- 兼題の管理元は公開サイトの `khb2027/js/kendai.json` に統一する。
- GASは投句の最終送信時、ロック取得前に同じ公開JSONを取得して全4兼題を検証する。
- 取得失敗・JSON不正・未設定の兼題がある場合は投句を保存せず、再試行を案内する。
- 新規投句・上書きの受付メールは、その送信で取得済みの兼題・読みを使用する。
- JSON取得後、ロック内で締切・エントリー・重複を再確認してから保存する。

### 重複投句と上書き

- 同一照合キーの既存投句は、最終送信の**前**に検知する。
- 全句・作者名・特記事項を含む内容が完全一致なら、`alreadySubmitted: true` と
  `同じ内容ですでに投句されています。` を返す。更新時刻・改訂番号・同意日時は比較対象外とする。
  上書き確認・再保存・履歴追加・メール再送は行わず、兼題取得も省略する。
- 内容が異なる既存投句がある場合、ページは「すでに投句を受け付けています。今回の内容で
  上書きしますか？」という確認ダイアログを表示する。
- 「キャンセル」では送信しない。「上書きする」を選んだ場合だけ、
  `overwrite: true` を付けて最終送信する。
- 期限内なら上書きを受理する。投句シートの正式データは最新内容とし、更新前の
  内容は履歴シートへ退避する。
- GASは最終送信時にも再度重複確認をする。事前確認から最終送信までの間に
  別送信があった場合、`overwrite: true` がなければ保存せず、再確認を促す。
- 上書き処理は `LockService` で排他制御し、同時送信による競合を避ける。
- 同一内容の判定も保存前のロック内で再実施し、同時送信でも重複保存しない。

### 作者ルール

- リーグ戦の3兼題は、各兼題内で3人の作者が異なることを必須とする（AABは不可）。
  異なる兼題で同じ作者が投句することはできる。
- 決勝戦の5句は、登録メンバー全員が1句以上投句することを必須とする。
  同じ作者の複数句・投句順は制限しない。3人ならAAABC、4人ならAABCD、5人ならABCDEが可能。
- 全兼題の作者名を、空白を除いた登録メンバーの氏名と照合し、未登録の作者の句を拒否する。
  リーグ戦の重複、決勝の全員参加も同じ比較基準を使う。文字自体の全半角・大小文字は変換しない。
  チーム名・メールの照合および同一投句内容の比較には、この氏名用の変換を適用しない。
- 同姓同名の場合は `氏名（所属校・学年）`、単独チームでは `氏名（学年）` で作者を区別する。
  別のメンバーの区別表記を使うことで、リーグ戦の作者重複と決勝の全員参加も確認する。
- フォームでは兼題内の重複と決勝の作者人数を確認し、GASでは登録氏名との照合も実施する。
  内容を変更する送信は事前確認と最終保存直前に、最新の名簿で検証する。

### メール本人確認と作者選択

- チーム照合後、利用者がボタンを押した場合だけ、GASのMailAppで登録メールへ6桁の確認コードを送る。
  クライアントから指定された別の宛先へは送らない。確認メールには運営BCCを付けない。
- コードは10分間有効・誤入力5回まで・一度だけ使用可能。コード送信ごとの `challengeId` で古いコードを区別する。
  再送は60秒間隔、チームごと日本時間の1日10通まで、全体は `KHB_AUTH_DAILY_LIMIT`（既定50通）まで。
  MailAppの残り送信枠が20以下の場合は、受付メールのために確認メール送信を停止する。
- コード状態・回数・再送間隔はScript Propertiesに保存し、LockService内で更新する。
  コードは秘密値とnonceによるHMACのみ保存し、平文は保存・ログ出力しない。前日以前の期限切れ状態を清掃する。
- 確認成功時に2時間有効のHMAC署名付きトークンを発行する。
  チーム名・メールの原値、照合キー、エントリーID・名簿・学校の情報を結び付け、改変や別チームでの利用を拒否する。
  名簿変更・エントリー無効化・期限切れでは再確認を必須にする。
- 本人確認済みの場合だけ作者の選択肢を返す。氏名・学年・所属校以外のエントリー情報は返さない。
  同姓同名は学年・所属校で区別し、すべて一致する場合は実行委員会への連絡を案内する。
- トークンはURLへ付けずPOSTで送る。画面ではタブ内のsessionStorageに保持し、完了・失効・チーム変更で消す。
  氏名一覧は公開JSONやブラウザーのストレージへ保存しない。選択した作者と投句の下書きは従来どおりsessionStorageに保持する。
- 作者一覧取得・事前確認・最終送信・保存直前で、GASがトークンと現在のエントリーを検証する。
  同一内容の投句でも本人確認を必須にし、認証なしで受付済みかを問い合わせることはできない。

## データ設計

同一のKHB専用スプレッドシートに以下を置く。

| シート | 用途 | 主な列 |
| --- | --- | --- |
| `エントリー` | 有効なエントリー | 受付時刻、エントリーID、学校名1〜5、出場予定チーム数、合同チーム、チーム名、責任者氏名・役割・メール、メンバー、紹介文、同意記録、照合キー、有効、備考 |
| `投句` | 各チームの現行・正式投句 | 更新時刻、照合キー、チーム名、メール、各句、作者名、特記事項、改訂番号 |
| `投句履歴` | 上書き前の投句の監査用保管 | 退避時刻、更新理由、元の投句行の全項目 |
| `運用ログ` | 不一致・期限後・競合などの記録 | 時刻、種別、照合キー、結果、補足 |

`エントリー`のチーム名・メールは運営管理用の原値として保存する。照合は照合キーで
行う。投句の照合キー列は非公開の管理列とする。

`エントリー` の `members` セルには、次の形式のJSON配列を保存する。
人数は既存の `memberCount` 列へ保存するため、列の追加は不要。

```json
[
  { "name": "文芸　太郎", "grade": "高3", "school": "" },
  { "name": "文芸　二郎", "grade": "高2", "school": "" },
  { "name": "文芸　三郎", "grade": "高1", "school": "" }
]
```

合同チームの `school` には、エントリーの学校名1〜5のいずれかをそのまま保存する。
受付メールではJSONを氏名・学年・所属校の一覧に整形する。
既存の自由記述形式の `members` は自動変換しない。運営が氏名と人数を確認して、
同じセルを上記JSONへ置き換える。未移行の登録では、内容を変更する投句を停止し、登録情報の確認を案内する。

## GAS構成

KHB専用のApps Scriptプロジェクトを作る。既存のお問い合わせ用GASとは分離する。

```text
Code.gs          doPost、レスポンス、共通エラー処理
config.gs        Script Propertiesの読み出し、受付期限、列定義
validation.gs    入力バリデーション
identity.gs      HMAC照合キー生成
entry.gs         エントリーの照合・保存
submission.gs    投句事前確認、保存、上書き、履歴退避
mail.gs          受付メールと運営通知
admin.gs         照合キー再作成などの管理処理
```

秘密値 `KHB_HMAC_SECRET` はScript Propertiesに設定する。その他の設定は
`gas/khb2027_webapp.gs` 冒頭の `KHB_CONFIG` にまとめる。
既存のScript Propertiesに同名の値がある場合は、そちらを優先する。
設定名は次のとおり。

```text
KHB_SPREADSHEET_ID
KHB_HMAC_SECRET
KHB_ENTRY_DEADLINE_JST
KHB_SUBMISSION_DEADLINE_JST
KHB_ADMIN_EMAIL
KHB_REPLY_TO
KHB_SITE_ORIGIN
KHB_AUTH_DAILY_LIMIT
```

## API仕様

すべてGAS Web Appの `POST /exec` に送る。リクエスト種別は `action` で識別する。
レスポンスは非表示iframeから `postMessage` で親ページへ返す。
各フォームは `responseOrigin: window.location.origin` を送信する。GASは `KHB_SITE_ORIGIN` と
`KHB_PREVIEW_ORIGINS`（カンマ区切り）の許可リストを照合し、許可した宛先だけへ結果を返す。
未指定・許可外は本番オリジンへ返す。成功・不一致・受付期間外・例外とも同じ応答先を使う。

ローカル確認は `http://127.0.0.1:8766` または `http://localhost:8766` を既定で許可する。
この変更をGASへ反映し、既存のデプロイを新しいバージョンに更新してからフォームを再読み込みする。
スプレッドシートIDなど既存の運用設定は保持する。`KHB_SITE_ORIGIN` は兼題取得にも使うため、
ローカルURLへ変更しない。別ポートを使う場合は `KHB_PREVIEW_ORIGINS` の方を更新する。

### 公開前の兼題で送信試験をする場合

ローカルの `khb2027/js/kendai.json` を編集しても、GASが取得する公開JSONは変わらない。
公開JSONの兼題が空欄の間は保存を停止する。試験用GASでは、Script Propertiesの
`KHB_TEST_TOPICS_JSON` にローカル `kendai.json` の全文を設定すれば、その兼題を使って試験できる。
設定中は公開JSONより優先するため、本番受付を開始する前にはこの設定を空に戻す。
ブラウザーが送る兼題や `responseOrigin` では取得元を切り替えない。
GASのコード更新は既存設定を保持したうえで新しいバージョンとして再デプロイする。

### `entry`

エントリーを受け付ける。

1. エントリー期限を確認する。
2. 入力をバリデーションする。
3. 照合キーを生成する。
4. 有効な同一照合キーの登録を確認する。
5. 未登録なら `エントリー` へ保存し、受付メールを送る。
6. 既登録なら保存せず、登録済みである旨を返す。

### `check-team`

投句フォームでチーム名とメールアドレスが両方入力されたら、最後の入力から400ms後に呼び出す。
俳句や宣誓は送信せず、投句受付期間、チーム情報の形式、有効なエントリーとの完全一致を確認する。
`requestId` を応答にも含め、入力変更前の応答を画面が採用しないようにする。
この処理では投句の保存・上書きやメール送信を行わない。
成功時は `memberCount` も返し、現在照合済みのチームに限って決勝の作者人数の確認に使う。
登録メンバーの氏名一覧はブラウザーへ返さない。

### `send-email-code` / `verify-email-code` / `get-author-options`

- `send-email-code`：有効なチーム・受付期間を確認し、送信制限の範囲内で登録メールへコードを送る。
  成功時は `challengeId`・`expiresAt`・`retryAfter` を返し、コードや名簿は返さない。
- `verify-email-code`：`challengeId` と `code` を確認し、成功時だけ `authorToken`・`expiresAt`・`authors` を返す。
  `authors` は選択肢の `value` と表示用の `label` の配列。名簿が不正・区別不能なら返さない。
- `get-author-options`：`authorToken` をサーバーで再検証して選択肢を返す。確認画面からの戻りや再読み込みで使う。
  無効なトークンには `requiresEmailVerification: true` を返す。
- 全処理に `requestId` を付け、入力変更前・別処理・異なるIDの応答を画面が採用しない。コード関連の応答待ちは45秒で解除する。

### `check-submission`

投句確認画面で、最終送信前に呼び出す。

1. 投句期限を確認する。
2. チーム名・メールおよび投句内容をバリデーションする。
3. 照合キーを生成し、有効なエントリーと本人確認トークンを確認する。
4. 同じ内容の現行投句があれば `alreadySubmitted: true` を返す。
5. 登録名簿に基づく作者ルールを確認し、異なる内容の既存投句の有無を返す。

成功レスポンス例：

```json
{ "source": "khb2027", "ok": true, "hasExistingSubmission": true }
```

### `submit-submission`

初回投句、または確認ダイアログで上書きが承認された後に呼び出す。

1. 投句期限、バリデーション、エントリー、本人確認トークンを再確認する。
   同じ内容の既存投句があればロック内で再照合し、保存せず `alreadySubmitted: true` を返す。
   それ以外は作者ルールを検証し、公開JSONから兼題を取得する。取得・検証の失敗時は保存しない。
2. `LockService` を取得する。
3. 締切、有効なエントリー、本人確認トークン、現行投句を再確認する。
   同じ内容なら保存せず応答する。それ以外は最新の登録名簿で作者ルールを再確認する。
4. 既存投句があり `overwrite` が偽なら、保存せず `requiresOverwrite` を返す。
5. 上書きなら既存行を `投句履歴` へ退避し、`投句` の現行行を更新する。
6. 初回なら `投句` に新規行を追加する。
7. 受付メール・運営通知を送信し、ロックを解放する。

## 画面改修

### エントリー

- 必須項目・条件付き必須項目・確認チェックが揃い、メール形式・紹介文の文字数・学校やメンバーの検証を通過するまで「エントリーする」を無効にし、投句フォームと同じ薄い表示にする。
  入力・選択・学校の追加削除で再判定する。送信中は無効状態を維持し、失敗後は現在の入力条件で再判定、成功後はフォームをリセットして無効に戻す。

- `khb2027/entry.html`、`khb2027/js/entry.js`、必要なCSSを追加する。
- お問い合わせフォームと同じく、通常のHTMLフォーム、非表示iframe、`postMessage`を使う。
- 合同チームと責任者の役割は、選択内容に応じて関連入力欄を表示・非表示にする。合同チーム時は
  2校目の学校名欄を必須とし、学校名は最大5校まで追加できる。
  非表示になった欄の値は送信前に消去する。
- 送信中はボタンを無効化し、成功・失敗を `aria-live` の領域で通知する。
- 人数変更時はメンバー入力を保持し、現在の人数分だけを送信する。
  合同チームの学校名変更時は所属校の選択肢も更新し、無効になった所属校を再選択させる。
- `khb2027/index.html` のエントリーリンクを `entry.html` に向ける。

### 投句

- 現行の `submit.html` と `confirm.html` の入力・確認体験は維持する。
- Google Formのentry IDと `formResponse` 送信は廃止する。対象は主に
  `khb2027/js/formIds.js`、`khb2027/js/submit.js`、`khb2027/js/confirm.js`。
- 確認画面の「送信」押下時に `check-submission` を実行する。
- 投句フォームでは `check-team` の結果をチーム情報の直下に表示し、チーム照合とメール本人確認が成功するまで「確認へ」を無効にする。
  チーム名・メールを書き換えると成功状態を解除して再照合する。IME変換中には照合せず、
  通信エラーや30秒のタイムアウト時には再確認ボタンを表示する。復元した入力も再照合する。
- チーム照合とメール本人確認の後に、投句欄全体を表示して入力を許可する。確認前は句・作者・特記事項・同意・「確認へ」を含むフィールドセットを非表示かつ無効にする。
  本人確認後は登録された作者の選択肢だけを表示し、テキストとして扱う。
  修正に戻った場合はトークンの再検証後に選択を復元し、期限切れなら投句の下書きを残して本人確認をやり直す。
- 既存投句がない場合は、そのまま `submit-submission` を実行する。
- 同一内容ならメッセージを表示し、「送信」を無効化して「修正に戻る」を有効にする。
  完了ページへは遷移せず、入力データを保持する。
- 内容が異なる既存投句がある場合のみ、アクセシブルな確認ダイアログを出す。
  - 文言：`すでに投句を受け付けています。今回の内容で上書きしますか？`
  - 操作：`キャンセル` / `上書きする`
  - キャンセルは確認画面に留まり、送信しない。
  - 上書きする場合だけ `overwrite: true` を送る。
- GASの成功応答を受け取ってから `finish.html` へ遷移する。
- 「送信」を押した時点から照合・保存・上書き確認・完了遷移まで「送信」「修正に戻る」を無効にする。
  エラー・上書きキャンセル（Escを含む）・90秒の応答タイムアウト後は操作を再開できる。
  送信結果の受信タイムアウトでは受付済みの可能性も案内し、入力データは保持する。
- 状況・エラー表示は固定ヘッダー内の「修正に戻る」の左に、両ボタンと同じ行に置く。
  空欄時も高さを確保し、長文は欄内をスクロールさせて、メッセージの有無で俳句欄の高さを変えない。
  画面幅によるヘッダーの実際の高さに合わせて俳句欄を配置する。
  成功時だけ投句用のsessionStorage項目を消去する。他ページのデータは消去しない。
- 各送信に `requestId` を付け、GASの全応答に同じ値を返す。確認画面は処理種別とIDを照合する。
  IDを返さない旧GASの応答は、実行中の処理種別が一致する場合に受け付ける。

## 実装順序

1. 本仕様に基づき、スプレッドシートの4シートとヘッダーを作成する。
2. KHB専用GASプロジェクトを作成し、Script Propertiesを設定する。
3. `validation.gs` と `identity.gs` を実装・単体確認する。
4. `entry` API、`entry.html`、`entry.js` を実装する。
5. テスト用チームでエントリー受付、重複エントリー、期限後停止を確認する。
6. `check-submission` API を実装する。
7. 投句の最終送信を `submit-submission` APIへ置き換える。
8. 上書き確認ダイアログ、履歴退避、排他制御を実装する。
9. 自動返信・運営通知を実装する。
10. テスト用シートと本番相当の締切時刻で、通し試験を行う。
11. 本番スプレッドシート、GAS `/exec` URL、サイトのリンクを切り替える。

## 受入テスト

- 新規エントリーで照合キーが作成され、受付メールが届く。
- 同じチーム名・メールの重複エントリーは保存されない。
- 合同チームのチェック時だけ2校目の学校名欄が表示・必須になり、最大5校まで増やせる。解除時には2校目以降の値が送信されない。
- 責任者の役割で`その他`を選んだ場合だけ具体的な役割欄が表示・必須になる。
- 有効なエントリーと完全一致する投句は受理される。
- チーム照合だけでは作者一覧が返らず、確認コードのメールも自動送信しない。
- コードの期限・誤入力5回・一度限りの使用・再送間隔・送信上限をGASで強制する。
- 登録先にだけ確認メールが届き、平文コード・トークンをシートやログ・運営BCCに記録しない。
- トークンの改変・別チームでの使用・名簿変更・受付無効化・期限切れでは、一覧取得・同一内容判定・投句保存を拒否する。
- 兼題取得中に名簿や期限が変わった場合も、保存直前に再確認する。
- チーム情報の変更・コード確認の遅延応答・通信失敗で古い作者一覧を表示しない。
- チーム照合→メールコード→作者選択→確認→保存の流れと、修正に戻る際の選択復元を確認する。
- チーム情報だけで自動照合でき、片方が未入力・形式不正・IME変換中には送信しない。
- 入力変更前の遅延応答では「確認へ」を有効にしない。通信失敗後は再確認できる。
- チーム名またはメールの表記が1文字でも異なる投句は受理されない。
- 初回投句では上書き確認を表示しない。
- 二回目の投句で内容が異なる場合は、保存前に上書き確認を表示する。
- 同一内容は、事前確認時・最終送信時・同時保存後のいずれで検出しても、再保存・履歴追加・メール再送をしない。
- 同一内容の表示後は送信できず、修正に戻れる。メッセージの表示で俳句表示領域の高さが変わらない。
- 3〜5人のメンバー入力、人数変更後の保持、空白を除いた氏名重複の警告・空白だけの入力拒否、合同チームの所属校を確認する。
- 学年リストの中1〜中3・高1〜高3と人数変更後の選択保持を確認し、改変されたリスト外の値をGASで拒否する。
- 姓名間の全角・半角スペースを認め、区切りなし・前後だけの空白・タブだけの区切りを責任者・メンバーとも拒否する。
- 合同チームの学校名重複は拒否し、修正や合同解除後にエラーを消す。
- 合同チームで全校からの選手登録を確認する。学校の追加・削除・改名、人数変更、所属校変更、合同解除で再判定し、学校数が選手数より多い場合も送信できないことを確認する。
- 同姓同名は学年・所属校が異なれば登録可能で、両方一致する場合は要連絡になる。
- リーグ戦は各兼題のAABを拒否し、異なる兼題間の同じ作者は許容する。
- 決勝は3人のAAABC・4人のAABCD・5人のABCDEを受理し、1人でも欠けた場合は拒否する。投句順を変えても同じ判定になる。
- 空白の有無・位置が異なる氏名は同じ登録者と判定し、入力表記はシート・メールへそのまま保存する。
- 未登録の作者・空白以外の文字が異なる氏名・未移行の名簿は、ブラウザーの確認を回避してもGASが拒否する。
- 保存直前に名簿が変わった場合も、最新の名簿に基づいて保存を止める。
- 上書きをキャンセルすると、投句内容は変わらない。
- 上書きを承認すると、現行投句が更新され、旧内容が履歴へ残る。
- 締切後は、エントリー・投句・上書きのすべてが保存されない。
- 同時送信時に、投句の現行行と履歴の対応が壊れない。
- `file://` ではなくHTTP経由で、PC幅とスマートフォン幅の送信フローを確認する。
