# 情報リテラシー研修の試験

研修トップの「確認試験を受ける」から開きます。URLは `/members/itlit/exam/`。ビルド不要でGitHub Pagesに配置できます。メンバー共通パスワードに加え、試験開始・再開時に氏名とメールで照合します。

## 問題・正答・合否条件

### 2026年度の設定

両種別 `2026-tech-pdf-1` は `2026_技術_extracted.txt` を基にした実問題の設定です。管理者レビューと2026-09-08の原文更新を反映しています。解答3の変更に伴う採点データを更新しました。

| 種別 | 解答欄数 | 大問別配点 | 合格点 | 時間 |
| --- | ---: | --- | ---: | ---: |
| 技術（筆記） | 32 | 15 / 20 / 25 / 25 / 15 | 80 / 100 | 60分 |
| 技術（筆記・実務） | 44 | 10 / 15 / 20 / 15 / 10 / 30 | 80 / 100 | 60分 |

両種別とも `forbiddenLimit: 1`。禁忌肢は提出時（時間切れを含む）の確定回答で判定し、提出前は修正できます。得点が合格点以上でも、禁忌肢が1問でも含まれれば不合格です。更新された冊子の「点数にかかわらず不合格」という注意事項と整合しています。解答上の注意は原文どおり配信本文に収録し、提出時判定の説明を併記しています。

問題表示は `2026_技術_assessment_1.pdf`（全52ページ）です。筆記は4～23ページ、筆記・実務は24～51ページで、`pdf` の `#page=4` / `#page=24` により各種別の開始ページを指定しています。共通の注意事項は1ページです。開始前の案内と別タブリンクにも対象ページを表示します。PDFビューアによって開始ページ指定が反映されない場合は、案内のページへ移動してください。今回の差し替えで正答・配点・禁忌肢のハッシュは変更していません。PDFのURLを含む設定が変わるため、旧版の保存記録は再開できません。

解答・禁忌肢の番号、各問の解説と補正理由を含む管理者用Markdown、および編集用JSONは公開リポジトリ外に保存します。公開用データには平文正答を追加しないでください。以前の操作確認版から設定が変わるため、その版の保存記録は再開できません。

正答と禁忌肢はsalt付きSHA-256で照合します。公開する `exam-data.js` に正答番号を書かず、以下の手順で `questions` を生成してください。

1. 問題PDFを `assets/exams/` に配置し、`pdf` に相対パスを設定します。
2. このリポジトリ・GitHub Pagesの公開フォルダーの外に、非公開の `questions.json` を作成します。次は書式例です。

```json
[
  { "answer": [6], "points": 30, "forbidden": [9] },
  { "answer": [4, 7], "points": 70, "forbidden": [] }
]
```

3. Node.js 18以降で生成します。Windows PowerShellではUTF-8で標準入力へ渡してください。

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
Get-Content -Raw -Encoding utf8 C:\private\questions.json | node members/itlit/exam/create-question-hashes.cjs
```

4. 出力された配列を `exam-data.js` の `questions` に貼り付けます。原文の `answer`・`forbidden` は貼り付けません。
5. `durationMinutes`（分）、`passScore`（合格点）、`forbiddenLimit`（禁忌肢で不合格となる設問数）を設定し、`version` を更新します。

生成結果は `salt`・`answerHash`・`points`・`forbiddenHashes` です。設問ごとにランダムな16バイトのsaltを生成します。原本のJSONは非公開で保管してください。再生成するとsaltが変わり、保存済み受験との設定一致が失われるため、受験中の再生成は避けます。

全問で1～9を複数選択でき、正答の集合と完全一致した場合のみ得点します。順序不問、余分・不足・未回答は0点、部分点なしです。禁忌肢は選んだ設問数で数え、同じ問で2つ選んでも1問です。`forbiddenLimit: 1` なら1問以上、`2` なら2問以上で不合格、`null` なら無効です。

結果は得点と合否だけです。`title`・`certificateIssuer`・`certificateText` で試験名と証明書を変更できます。PDF未設定時は `sampleText` を表示しますが、正答・禁忌肢の説明は書かないでください。

### ハッシュと注意表示の仕様

次の配列をJSON文字列・UTF-8でSHA-256化します。正答は昇順に並べ、禁忌肢は1個ずつ種類を分けてハッシュ化します。

```js
['klea-answer-v1', salt, 'answer', 回答番号の昇順配列]
['klea-answer-v1', salt, 'forbidden', [選択番号]]
```

公開設定を開いただけでは番号が読めなくなりますが、saltと採点処理は公開されます。選択は512通りなので、総当たりを防ぐ機能ではありません。以前公開した正答はGit履歴などに残る可能性もあります。

`app.js` の冒頭でコンソールに色付き注意文を表示します。公正な受験と、知らないコードを貼り付けないことを呼びかけます。開発者ツールの検知・妨害はしません。ログ消去やフィルターで非表示にできます。

## 試験種別を増やす

同じ研修内では `window.EXAMS` 配列に既存の設定オブジェクトをコピーし、カンマで区切って追加します。

1. `id` を重複しない値に変更し、`title`・`version` を設定。
2. PDFを追加し、`pdf` の相対パスを変更。
3. 上記ツールでその試験の `questions` を生成して貼り付け。
4. 制限時間・合否条件・証明書文言を変更。

選択欄へ自動で追加され、問題数は `questions` の件数で決まります。受験者ハッシュは同じ研修内で共通、保存記録は研修URLごとに1件です。別研修ではその研修内に `exam/` をコピーし、試験設定・登録ハッシュ・リンクを変更します。

### 設定エラーの場合

設定エラーの試験も一覧に残り、選択すると原因を表示します。正常な試験は利用できます。

- `passScore` は割合ではなく点数です。30点満点で8割合格なら24です。80点にするなら配点合計も80点以上にしてください。
- `questions` は生成されたハッシュ形式を使用します。古い `answer`・`forbidden` 形式は受け付けません。
- `id` の重複、カンマ・括弧・引用符を確認します。構文は以下で検査できます。

```sh
node --check members/itlit/exam/exam-data.js
```

## 受験者の登録

現在は `access-data.js` の `hashes` が照合先です。初期状態は空なので受験できません。不一致・設定エラーも開始を許可しません。

Node.js 18以降で次を実行し、氏名・メールを対話入力します。

```sh
node members/itlit/exam/create-hash.cjs
```

出力された64文字の小文字16進数を `access-data.js` の `hashes` 配列に文字列として追加します。氏名・メールの原文をリポジトリに登録しないでください。ツールは原文をファイルに保存しませんが、対話入力は端末に表示されます。

`hash1`・`hash2` などの例示文字列は登録しないでください。配列に1件でも64文字の小文字16進数ではない値があると照合を停止し、不正なデータの位置を表示します。

登録ツールと受験画面は同じ `identity.js` を使用します。

1. 氏名：Unicode NFKC正規化 → 前後空白除去 → 連続空白を半角スペース1つに統一。
2. メール：Unicode NFKC正規化 → 前後空白除去 → 全体を小文字化。
3. `JSON.stringify(['klea-identity-v1', 正規化氏名, 正規化メール])` をUTF-8で符号化。
4. SHA-256 → 小文字16進数64文字。

「山田 太郎」と「山田太郎」は別です。姓名間の空白の有無は登録時に揃えてください。方式の変更時は登録ハッシュも再生成します。

将来のDB接続では、`ExamIdentity.authorize(name, email, config)` をAPI照合に置き換えます。成功時は `{ id: ハッシュ, name: 正規化氏名 }` を返し、不一致・通信失敗時は例外にします。秘密のDB接続情報はAPIサーバー側に保持します。現時点で外部DBへの接続はありません。

静的サイトではハッシュ一覧と照合処理が公開され、回避も可能です。ハッシュは匿名化・本人確認・メール所有確認を保証しません。厳密な受験制御が必要なら、照合と試験配信・提出をサーバーで認可します。

## 保存と再開

照合に成功すると開始確認画面を表示します。新規受験は「試験開始」を押した時点で記録を保存し、制限時間を開始します。照合しただけでは開始しません。開始済みの記録は「試験を再開」、提出済みの記録は「結果を表示」から進みます。再開前の確認画面でも既存の終了予定時刻は変わりません。

PCでの受験を推奨します。受験中は画面の高さを固定し、左のPDFビューア（仮問題の場合は問題本文）と右の回答一覧を独立してスクロールできます。タイマーと提出ボタンは表示したままです。狭い画面では左右の領域全体を横スクロールして切り替えます。各問のクリアボタンはマークの右端に配置しています。

研修URLごとに受験記録1件をlocalStorageに保存します。氏名・ハッシュID・試験設定・回答・開始時刻・終了予定時刻・提出時刻を保存し、メール原文は保存しません。再読み込み時は氏名・メールを再照合して再開・結果表示します。登録を削除された受験者は再開できません。

閉じている間や照合中も時間は進み、期限後の再開時は保存済み回答を自動提出します。設定変更後は以前の記録の再開を停止します。保存不可の環境では開始できません。「新しく受験する」で記録を削除できます。旧 `/exam/` の単一選択記録は移行しません。

別研修には、その研修フォルダー内に `exam/` をコピーして試験データ・登録ハッシュ・研修へのリンクを変更します。階層が異なる場合は共通CSS・認証スクリプトの相対パスも調整します。

PDFは埋め込み表示と別タブ表示に対応。合格時は証明書を印刷・PDF保存できます。端末時計の変更、ブラウザデータ削除、公式証明書発行、結果収集は対象外です。
